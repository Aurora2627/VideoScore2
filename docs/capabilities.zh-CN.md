# ClipRank 能力评估与面试准备

| 能力 | 项目中已有证据 | 体现程度 |
|---|---|---|
| 视频多模态输入处理 | 帧采样、最长边缩放、视频与提示词配对；对照 224/448 输入配置 | 较强，可解释采样与信息损失的权衡 |
| 资源受限的模型推理 | NF4 双重量化、BF16、SDPA、常驻模型逐视频执行、输出完整性与评分校验 | 较强；使用现有组件，无自定义 CUDA 内核 |
| PyTorch 训练 | 冻结特征、训练集标准化、线性/MLP 头、SmoothL1、同提示词排序损失、早停与多种子集成 | 中等，训练范围是轻量评分头 |
| 数据划分与泄漏控制 | 提示词组隔离、排除已调试组、验证选择模型后再测试、骨干见过训练数据的边界说明 | 较强 |
| 评测与误差分析 | MAE、Pearson/Spearman、候选排序、提示词组 bootstrap 与失败案例；保留退步结果 | 较强，但样本和可比较候选对仍少 |
| 应用工程与可追踪性 | 输入哈希、模型/数据版本、源码快照、日志、Git 标签、HTML 人工复核 | 较强；尚无线上业务指标或大规模负载验证 |
| VLM 主干微调与偏好优化 | 本项目未更新主干，也未做 LoRA/SFT/DPO/GRPO | 尚不能证明 |
| 图像/视频生成与编辑 | 本项目对生成结果评分，没有训练或编辑生成模型 | 尚不能证明 |

以上是项目可以支持的能力证据，不代表已经测验过个人掌握程度。

## 优先掌握的问题

1. 视频如何进入多模态模型？为什么选 4 帧与 448 输入？什么时候会漏掉时序错误？
2. NF4、双重量化、BF16 和 SDPA 分别改变什么？推理量化和训练量化有什么区别？
3. 从哪个 token 读取特征，为什么不能把人工评分/解释放入输入？如何处理 padding？
4. 为什么按提示词分组划分，而不是随机打散视频？骨干先前训练过同源数据意味着什么？
5. SmoothL1、排序损失和三种子集成分别解决什么问题？为何评分头没有超过原模型？
6. MAE、相关性和同提示词排序为什么可能相互矛盾？如何处理并列？
7. 为什么按提示词 bootstrap？置信区间跨零能得出什么结论？
8. 评分规则权重、分数阈值是否经过业务校准？发生解析失败时如何处理？

## 项目定位

适合展示多模态评测、视频质量分析和算法工程能力；作为多模态算法简历的一项完整项目，有真实模型推理、训练和独立对照证据。算法创新深度与大模型后训练能力仍有限，后续生成/编辑项目可补足另一方向，不能把本项目描述为训练视频生成模型。
